# Testing and Viva Preparation

## Required tests for every Data Structure
Test:
- Empty structure behavior.
- Insert one item.
- Insert multiple items.
- Search/retrieve.
- Delete/remove where supported.
- Boundary conditions.
- Duplicate handling.
- Correct ordering/traversal.
- Complexity explanation.

## Application integration tests
1. Add a memory and verify it appears on dashboard and Memory Vault.
2. Close and reopen app; verify the memory persists.
3. Edit the memory; verify updated values.
4. Archive it; verify it disappears from active views.
5. Restore it; verify it returns.
6. Search by ID and keyword.
7. Add a document with a sample file path and handle missing file.
8. Connect two records and verify both show as neighbors.
9. Verify BFS and DFS traversal.
10. Verify priority 5 is returned before priority 1.
11. Verify undo for each supported action.
12. Verify no records are lost after app restart.

## Viva questions
- Why did you choose LifeVault?
- What is the difference between an Array and Linked List?
- Why is Stack suitable for Undo?
- Explain FIFO and LIFO.
- Why is Circular Linked List suitable for cyclic memory browsing?
- How does BST search work?
- What is the category Tree in this project?
- What is a Graph vertex and edge here?
- Explain BFS and DFS.
- How does a Heap/Priority Queue work?
- What is hashing?
- What is collision and how does chaining handle it?
- Why use SQLite if Data Structures are implemented?
- Why rebuild in-memory structures after restarting?
- What is the time complexity of each structure?
- Which features use each Data Structure in the running application?

## Demonstration rule
Viva explanations must match the actual source code. Never describe a feature as implemented if it is only planned.
